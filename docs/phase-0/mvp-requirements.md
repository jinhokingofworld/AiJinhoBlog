# MVP 요구사항 정리

## 1. 목적

이 문서는 AiJinhoBlog의 MVP 범위를 확정하고, 이후 Phase 1부터 구현할 기능의 기준을 정리한다.

MVP의 목표는 단순한 블로그에 AI 기능을 얹는 것이 아니라, 사용자의 과거 글을 실제 지식 기반으로 저장하고 다시 활용할 수 있는 최소 동작 흐름을 완성하는 것이다.

## 2. 핵심 사용자 흐름

### 2.1 인증 흐름

1. 사용자는 회원가입 화면에서 계정을 만든다.
2. 사용자는 로그인 화면에서 인증한다.
3. 로그인한 사용자는 게시글 작성, 수정, 삭제, AI 기능에 접근할 수 있다.
4. 로그인하지 않은 사용자는 보호된 기능에 접근할 수 없다.
5. 사용자는 로그아웃할 수 있다.

### 2.2 게시글 작성 흐름

1. 로그인한 사용자는 제목, 본문, 태그를 입력해 게시글을 작성한다.
2. 게시글 저장 시 기본 게시글 데이터가 MySQL에 저장된다.
3. 게시글 본문은 검색과 RAG에 사용할 수 있도록 전처리된다.
4. 전처리된 텍스트는 chunk 단위로 나뉜다.
5. 각 chunk는 임베딩되어 ChromaDB에 저장된다.
6. 저장이 완료되면 사용자는 작성한 게시글 상세 화면으로 이동한다.

### 2.3 게시글 조회와 탐색 흐름

1. 사용자는 게시글 목록을 최신순으로 조회한다.
2. 사용자는 페이지 단위로 게시글 목록을 탐색한다.
3. 사용자는 키워드로 제목과 본문을 검색한다.
4. 사용자는 태그를 기준으로 게시글을 필터링한다.
5. 사용자는 게시글 상세 화면에서 본문, 태그, 댓글을 확인한다.

### 2.4 게시글 수정과 삭제 흐름

1. 게시글 작성자는 자신의 게시글을 수정할 수 있다.
2. 게시글 수정 시 MySQL의 게시글 데이터가 갱신된다.
3. 게시글 수정 시 기존 벡터 데이터는 삭제 또는 갱신되고, 새 본문 기준으로 다시 인덱싱된다.
4. 게시글 작성자는 자신의 게시글을 삭제할 수 있다.
5. 게시글 삭제 시 댓글, 태그 연결, 벡터 데이터가 함께 정리된다.

### 2.5 댓글 흐름

1. 로그인한 사용자는 게시글 상세 화면에서 댓글을 작성한다.
2. 댓글 작성자는 자신의 댓글을 삭제할 수 있다.
3. 게시글 작성자는 자신의 게시글에 달린 댓글을 삭제할 수 있다.
4. 댓글 삭제 후 게시글 상세 화면의 댓글 목록이 갱신된다.

### 2.6 과거 글 기반 Q&A 흐름

1. 로그인한 사용자는 자연어 질문을 입력한다.
2. 시스템은 질문을 임베딩한다.
3. ChromaDB에서 관련 게시글 chunk를 검색한다.
4. 검색 결과를 근거로 답변을 생성한다.
5. 답변에는 참고한 게시글 제목 또는 링크가 함께 표시된다.
6. 관련 근거가 부족하면 시스템은 추측 대신 근거 부족 상태를 알려준다.

### 2.7 유사 글과 중복 작성 방지 흐름

1. 사용자가 새 글 제목 또는 본문을 입력한다.
2. 시스템은 기존 게시글과의 유사도를 계산한다.
3. 유사도가 높은 게시글이 있으면 목록과 간단한 사유를 보여준다.
4. 발행 직전 중복 가능성이 높으면 사용자에게 경고한다.
5. 사용자는 경고를 확인한 뒤 발행을 계속할 수 있다.

### 2.8 외부 자료 저장 흐름

1. 사용자는 외부 링크나 이미지를 저장 대상으로 입력한다.
2. 시스템은 입력 자료의 제목, 핵심 내용, 출처를 추출한다.
3. 추출 결과는 게시글 초안 형태로 저장된다.
4. 사용자는 초안을 수정한 뒤 게시글로 발행할 수 있다.

### 2.9 글감 추천과 문체 변환 흐름

1. 시스템은 사용자의 최근 게시글 빈도와 주제를 분석한다.
2. 시스템은 최근 관심사와 과거 글을 기준으로 글감 후보를 제안한다.
3. 사용자는 외부 텍스트 또는 초안을 입력한다.
4. 시스템은 사용자의 기존 글을 참고해 문체를 반영한 수정안을 생성한다.
5. 사용자는 원문과 수정안을 비교할 수 있다.

## 3. MVP 포함 범위

### 3.1 기본 블로그

- 회원가입, 로그인, 로그아웃
- 게시글 생성, 목록 조회, 상세 조회, 수정, 삭제
- 댓글 작성, 삭제
- 태그 저장과 태그별 조회
- 게시글 목록 페이징
- 제목과 본문 키워드 검색

### 3.2 데이터 저장

- MySQL 기반 사용자, 게시글, 댓글, 태그 데이터 저장
- 게시글과 사용자 권한 관계 관리
- 게시글과 태그의 다대다 관계 관리

### 3.3 AI 데이터 파이프라인

- 게시글 본문 전처리
- chunk 분할
- OpenAI Embedding 호출
- ChromaDB 컬렉션 저장
- 게시글 수정과 삭제에 따른 벡터 데이터 갱신
- AI 요청 실패 시 사용자에게 이해 가능한 오류 반환

### 3.4 RAG 기능

- 과거 글 기반 Q&A
- 답변 근거 게시글 표시
- 제목 또는 본문 기준 유사 게시글 검색
- 게시글 발행 전 중복 가능성 알림

### 3.5 MCP 기능

- Dropbox MCP를 통한 문서 목록 조회와 검색
- 자체 MCP 서버의 게시글 목록, 상세, 생성, 수정, 삭제 tool
- 외부 링크 입력 후 내용 추출과 게시글 초안 저장
- 이미지 입력 후 분석 결과를 게시글 초안으로 저장

### 3.6 Agent 기능

- 최근 게시글 기반 관심 주제 요약
- 글감 추천
- 사용자 문체 프로파일 생성
- 사용자 문체 기반 재작성
- 원문과 재작성 결과 비교

## 4. MVP 제외 범위

다음 기능은 MVP 이후 Future Scope로 미룬다.

- 수천 개 이상 게시글을 대상으로 한 대규모 트렌드 리포트
- 자동 DB 정규화와 태깅 고도화
- 여러 사용자를 대상으로 한 공개 커뮤니티 운영 기능
- 관리자 대시보드
- 결제, 구독, 사용량 제한 요금제
- 모바일 앱
- 실시간 협업 편집
- 고급 통계 대시보드
- 완전 자동 출판 워크플로
- 여러 LLM Provider 전환 UI

## 5. 기능별 완료 조건

### 5.1 인증

- 사용자는 회원가입 후 로그인할 수 있다.
- 중복 이메일 또는 중복 아이디는 저장되지 않는다.
- 비밀번호는 평문으로 저장되지 않는다.
- 로그인하지 않은 사용자는 보호된 API와 화면에 접근할 수 없다.
- 로그아웃 후 보호된 기능에 접근하면 로그인 화면으로 유도된다.

### 5.2 게시글

- 로그인한 사용자는 게시글을 작성할 수 있다.
- 게시글 목록은 최신순으로 조회된다.
- 게시글 상세 화면에서 제목, 본문, 작성자, 작성일, 태그가 표시된다.
- 작성자만 자신의 게시글을 수정하거나 삭제할 수 있다.
- 삭제된 게시글은 목록과 상세 조회에서 보이지 않는다.

### 5.3 댓글

- 로그인한 사용자는 게시글에 댓글을 작성할 수 있다.
- 댓글 작성자와 게시글 작성자는 댓글을 삭제할 수 있다.
- 권한이 없는 사용자는 댓글을 삭제할 수 없다.
- 댓글 삭제 후 화면에 삭제 결과가 반영된다.

### 5.4 태그와 탐색

- 게시글 작성 시 태그를 함께 저장할 수 있다.
- 게시글 목록에서 태그별 필터링이 가능하다.
- 제목과 본문 키워드 검색이 가능하다.
- 검색어와 태그 필터를 함께 사용할 수 있다.
- 목록 조회는 페이지 단위로 동작한다.

### 5.5 벡터 인덱싱

- 게시글 생성 시 ChromaDB에 관련 chunk가 저장된다.
- 게시글 수정 시 기존 chunk가 최신 본문 기준으로 갱신된다.
- 게시글 삭제 시 관련 chunk가 삭제된다.
- 벡터 저장 실패 시 게시글 저장 상태와 사용자 안내가 일관되게 처리된다.

### 5.6 과거 글 기반 Q&A

- 사용자는 자연어 질문을 입력할 수 있다.
- 시스템은 관련 게시글 chunk를 검색한다.
- 답변에는 참고한 게시글 정보가 표시된다.
- 근거가 부족하면 근거 부족 메시지를 반환한다.
- 다른 사용자의 비공개 게시글은 검색 근거로 사용되지 않는다.

### 5.7 유사 글과 중복 알림

- 새 글 제목 또는 본문 기준으로 유사 게시글을 찾을 수 있다.
- 유사 게시글 목록에는 제목, 간단한 이유, 유사도 기준이 표시된다.
- 발행 직전 중복 가능성이 높으면 경고가 표시된다.
- 사용자는 경고를 무시하고 발행할 수 있다.

### 5.8 MCP 연동

- Dropbox MCP 인증과 검색 실패가 구분되어 표시된다.
- Dropbox 문서 목록을 조회할 수 있다.
- Dropbox 문서 내용을 검색해 글 작성 참고 자료로 사용할 수 있다.
- 자체 MCP 서버는 게시글 CRUD tool을 제공한다.
- 외부 링크나 이미지 분석 결과를 게시글 초안으로 저장할 수 있다.

### 5.9 Agent 기능

- 최근 게시글 기준 관심 주제를 요약할 수 있다.
- 글감 추천 결과에는 추천 이유와 관련 과거 글이 포함된다.
- 사용자 문체 프로파일은 과거 게시글을 기준으로 생성된다.
- 문체 변환 결과는 원문과 함께 비교할 수 있다.
- AI 결과는 사용자가 수정 가능한 초안 형태로 제공된다.

## 6. 후속 작업 기준

Phase 1부터는 이 문서의 완료 조건을 기준으로 이슈를 생성한다.

기능 구현 이슈를 만들 때는 다음 항목을 반드시 포함한다.

- 어떤 사용자 흐름을 구현하는지
- 어떤 데이터 모델 또는 API가 필요한지
- 권한과 실패 케이스가 무엇인지
- 어떤 명령어 또는 화면으로 검증할지
- AI 기능인 경우 어떤 근거 데이터와 비용 기록이 필요한지
