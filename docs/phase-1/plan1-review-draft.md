# Phase 1 재설계 검토용 상세 계획서

## 문서 목적

이 문서는 기존 `plan1.md`를 덮어쓰지 않고, Phase 1 요구사항을 다시 검토하기 위한 새 초안이다. 사용자가 각 항목에 직접 코멘트를 달고, 기능 설정값과 화면 흐름을 확정할 수 있도록 체크리스트를 세분화한다.

현재 문서는 구현 지시서가 아니라 `계획 수립` 단계의 검토 문서다. 이 문서에 대한 사용자 코멘트가 반영된 뒤에만 `계획 수정 -> 이슈 생성 -> 브랜치 생성 -> 구현 -> 커밋/이슈 종료 -> 브랜치 제거` 순서로 진행한다.

## 중요한 원칙

- 기존 Phase 1 구현은 참고 자료로만 본다.
- 기존 구현에 들어간 API 엔드포인트, 라우트, 화면 구성을 확정값으로 간주하지 않는다.
- 변수명, 함수명, 파일명처럼 구현 내부에서만 쓰는 값은 개발자가 정할 수 있다.
- API 엔드포인트, 공개 라우트, 사용자에게 보이는 기능명, 인증 흐름, 폴더/프로필/게시글 정책 같은 기능 설정값은 사용자가 결정한다.
- 사용자가 이미 지정한 값은 확정 후보로 표시한다.
- 사용자가 아직 지정하지 않은 값은 임의로 정하지 않고 `결정 필요`로 남긴다.
- 사용자가 `네가 설정해`, `알아서 해`라고 명시한 기능 설정값은 개발자가 초안을 제안할 수 있다. 단, 이 문서에서는 `개발자 제안`으로 표시하고 사용자가 승인하기 전까지 최종 확정값으로 보지 않는다.
- AI 활용 기능은 Phase 1 구현 대상이 아니다. Phase 1에서는 나중에 AI 요약, 추천, RAG, 글쓰기 보조를 붙일 수 있는 데이터/화면 확장 지점만 고려하고, 실제 AI 호출, ChromaDB 인덱싱, RAG 파이프라인, 요약 생성 로직은 만들지 않는다.

### 추가 확인이 필요한 지점

- [ ] `username`은 URL에 들어가므로 중복 불가 정책이 필요하다.
- [ ] `username`에 허용할 문자, 길이, 변경 가능 여부를 정해야 한다.
- [ ] `/login`, `/signup`, `/api`, `/admin`처럼 `/{username}`과 충돌할 수 있는 예약어 목록이 필요하다.
- [ ] 실명을 공개 블로그에 표시하므로 개인정보 노출 정책을 확인해야 한다.
- [ ] JWT를 어디에 저장할지 정해야 한다.
  - 결정 필요: httpOnly cookie
  - 결정 필요: localStorage
  - 결정 필요: access token + refresh token 분리
- [x] `처음 로그인하면 기본 폴더 1개, 기본 글 1개`는 첫 로그인 직후 생성한다.
- [ ] 기본 폴더 이름과 기본 글 제목/본문을 정해야 한다.
- [x] AI 요약, AI 추천, RAG 같은 AI 활용 기능은 Phase 1 구현 범위에서 제외하고, 추후 확장 시 막히지 않도록 데이터 구조와 UI 위치만 고려한다.
- [ ] 로컬 이미지 업로드 파일의 저장 위치와 배포 환경 지속성을 정해야 한다.
- [ ] 프로필 이미지와 커버 이미지의 허용 확장자, 용량 제한, 삭제 정책을 정해야 한다.
- [ ] 폴더 병합의 정확한 동작을 정의해야 한다.
  - 결정 필요: A 폴더의 글을 B 폴더로 이동 후 A 삭제
  - 결정 필요: 이름만 병합
  - 결정 필요: 중복 이름 폴더 자동 병합
- [ ] 게시글 상세 페이지에 `글 목록 5개만 표시`한다는 요구의 위치와 의미를 확정해야 한다.
  - 결정 필요: 상세 페이지 사이드바에 최근 글 5개 표시
  - 결정 필요: 상세 페이지 하단에 관련 글 5개 표시
  - 결정 필요: 상세 페이지에서 같은 폴더 글 5개 표시
- [ ] 글 작성 실패 시 `본인 페이지로 돌아가고 글을 다시 써야 한다`는 정책은 입력값 손실이 크므로 최종 확인이 필요하다.
  - 결정 필요: 실패해도 작성 폼 유지
  - 결정 필요: 본인 페이지로 이동
  - 결정 필요: 임시저장 후 이동

## 구현 전 승인 필요 체크리스트

아래 항목은 구현을 시작하기 전에 사용자가 승인하거나 값을 정해야 한다. 이 항목이 확정되지 않으면 이슈 생성 이후 구현 중에 API/라우트/데이터 모델을 다시 바꾸게 될 가능성이 높다.

- [ ] 개발자 제안 라우트를 승인한다.
  - 대상: `/{username}/posts/new`, `/{username}/posts/{postId}`, `/{username}/posts/{postId}/edit`, `/{username}/settings/profile`, `/account`, `/{username}/settings/folders`
- [ ] 개발자 제안 API 엔드포인트를 승인한다.
  - 대상: 인증, 프로필, 게시글, 댓글, 폴더, 태그 API
- [ ] JWT 저장 방식을 확정한다.
  - 개발자 제안: access token + refresh token을 httpOnly cookie 기반으로 관리한다.
- [ ] 로그아웃 후 이동할 화면을 확정한다.
- [ ] username 정책을 확정한다.
  - 대상: 허용 문자, 길이, 변경 가능 여부, 예약어 목록
- [x] 기본 폴더와 기본 글 생성 시점은 첫 로그인 직후로 둔다.
- [ ] 기본 폴더 이름과 기본 글 제목/본문을 확정한다.
- [ ] 프로필 이미지와 커버 이미지의 로컬 저장 정책을 확정한다.
  - 대상: 저장 위치, 허용 확장자, 용량 제한, 기존 파일 삭제 정책
- [ ] 폴더 병합 동작을 확정한다.
- [ ] 글 상세 페이지의 `글 목록 5개` 표시 위치와 의미를 확정한다.
- [ ] 글 작성 실패 시 이동/입력값 보존 정책을 확정한다.
- [ ] Phase 1에서는 AI 기능을 구현하지 않고 확장 지점만 남긴다는 범위를 승인한다.

### JWT 인증 설계 초안

JWT 적용은 사용자가 확정했다. 아래 세부 정책은 개발자 제안이며, 최종 구현 전에 승인한다.

- [ ] access token은 짧은 만료 시간으로 발급한다.
- [ ] refresh token은 별도 만료 시간을 둔다.
- [ ] token 저장 방식은 보안상 httpOnly cookie를 우선 제안한다.
- [ ] localStorage 저장은 XSS 위험이 있어 기본 제안에서 제외한다.
- [ ] 로그아웃 시 refresh token을 서버에서 무효화할 수 있도록 토큰 식별자를 저장한다.
- [ ] 현재 사용자 조회 API는 JWT 검증 후 사용자 정보를 반환한다.
- [ ] 토큰 만료 시 프론트엔드는 로그인 화면으로 이동한다.
- [ ] refresh token 자동 갱신을 Phase 1에 포함할지 결정한다.
  - 개발자 제안: Phase 1에는 refresh token 갱신까지 포함한다.

### AI 확장 대비 설계 메모

AI 활용 기능은 Phase 1에 구현하지 않는다. 다만 나중에 RAG, AI 요약, 추천, 글쓰기 보조를 붙일 때 구조를 갈아엎지 않도록 아래 정도만 고려한다.

- [ ] 게시글 데이터에는 추후 AI 요약을 저장할 수 있는 확장 여지를 둔다.
- [ ] Phase 1 UI의 게시글 카드에는 요약 표시 위치를 확보하되, AI 생성 호출은 하지 않는다.
- [ ] 요약 값이 없으면 본문 일부 또는 빈 상태를 표시하는 정책을 정한다.
- [ ] 글 작성/수정 저장 흐름은 AI 호출 실패에 영향을 받지 않도록 설계한다.
- [ ] 나중에 AI 요약을 비동기로 생성할 수 있도록 게시글 저장과 요약 생성을 분리할 수 있게 한다.
- [ ] ChromaDB 인덱싱은 Phase 2 이후 별도 이슈로 분리한다.
- [ ] RAG용 벡터 동기화는 게시글 작성/수정/삭제 이벤트와 연결할 수 있게 서비스 경계를 고려한다.

### 메인페이지 인증 분기 체크리스트

- [ ] 메인페이지가 어떤 라우트인지 확정한다.
  - 결정 필요: `/`
  - 결정 필요: 별도 블로그 홈 라우트
  - 결정 필요: 다른 이름
    > '/'는 블로그 소개 페이지로 두면 될 것 같아.
    > /{username} 이게 기본 블로그 홈이였으면 좋겠어.
    > 로그인이 되지 않은 상태에서 블로그 소개페이지 '/'로 접근해도 되게 만드는게 좋을 것 같아.
- [ ] `/`는 로그인 여부와 관계없이 접근 가능한 공개 소개 페이지로 둔다.
- [ ] `/{username}`은 로그인 여부와 관계없이 보기 권한으로 접근 가능하게 둔다.
- [ ] `/{username}`이 현재 로그인한 사용자의 블로그라면 글쓰기, 프로필 설정, 폴더 관리 버튼을 노출한다.
- [ ] `/{username}`이 다른 사람의 블로그라면 글쓰기, 프로필 설정, 폴더 관리 버튼을 숨긴다.
- [ ] 글 작성/수정/폴더 관리/프로필 설정 라우트는 로그인하지 않은 사용자가 접근하면 `/login`으로 이동시킨다.
- [ ] 글 작성/수정/폴더 관리/프로필 설정 라우트는 블로그 소유자가 아닌 사용자가 접근하면 접근 거부 화면 또는 블로그 홈으로 이동시킨다.
- [ ] 인증 확인 중 로딩 상태를 정의한다.
- [ ] 인증 API 실패 시 fallback 화면을 정의한다.

### 로그인 전 화면

    > 최신 결정: AI 기능은 Phase 1 이후 확장한다. Phase 1 안내 문구에서는 실제 AI 기능이 즉시 제공되는 것처럼 보이는 표현을 피한다.

    > 로그인
