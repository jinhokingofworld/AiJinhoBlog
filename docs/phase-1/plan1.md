# Phase 1 구현 계획

## 목표

Phase 1의 목표는 AI 기능을 얹기 전에 개인 블로그로서 동작하는 최소 기반을 완성하는 것이다. 회원가입/로그인, 게시글 CRUD, 댓글, 태그, 검색, 페이징을 먼저 안정화하고, 이후 RAG와 MCP가 참조할 수 있는 데이터 구조를 Prisma/MySQL 기준으로 고정한다.

## 범위

- Prisma 7 기반 MySQL 스키마를 정의한다.
- 사용자, 세션, 게시글, 댓글, 태그, 게시글-태그 연결 모델을 만든다.
- 쿠키 기반 세션 인증을 구현한다.
- 회원가입, 로그인, 로그아웃, 현재 사용자 조회 API를 만든다.
- 게시글 목록/상세/작성/수정/삭제 API를 만든다.
- 댓글 작성/삭제 API를 만든다.
- 태그 목록, 제목/요약 키워드 검색, 태그 필터, 기본 5개 페이지네이션을 제공한다.
- 기본 블로그 화면을 실제 API와 연결한다.
- 인증/입력 정규화 로직을 단위 테스트로 검증한다.
- CI에 Prisma 검증, Prisma Client 생성, 테스트 단계를 추가한다.

## 제외 범위

- RAG 임베딩 생성과 ChromaDB 색인 동기화는 Phase 2에서 구현한다.
- OpenAI API 연동, MCP 서버, Agent 기능은 기본 블로그 데이터 구조가 안정화된 뒤 진행한다.
- 이메일 인증, 비밀번호 재설정, OAuth는 MVP 이후로 미룬다.

## 완료 기준

- `plan1.md`가 Phase 1의 구현 범위와 검증 기준을 설명한다.
- `prisma validate`와 `prisma generate`가 성공한다.
- 회원가입/로그인 후 게시글과 댓글을 생성할 수 있다.
- 게시글 수정/삭제는 작성자만 가능하다.
- 댓글 삭제는 댓글 작성자 또는 게시글 작성자만 가능하다.
- 게시글 목록에서 키워드 검색, 태그 필터, 페이지 이동이 가능하다.
- `npm run lint`, `npm run format:check`, `npm run test`, `npm run build`가 통과한다.

## 작업 순서

1. Phase 1 계획을 정리하고 이슈를 생성한다.
2. 중간 이슈 기준 브랜치를 생성한다.
3. Prisma 스키마와 생성 설정을 추가한다.
4. 인증 유틸과 API 라우트를 구현한다.
5. 기본 블로그 화면을 API와 연결한다.
6. 단위 테스트와 CI 단계를 추가한다.
7. 검증 명령을 실행하고 문제는 `Problem.md`에 기록한다.
8. 관련 이슈 체크리스트를 갱신한 뒤 커밋한다.
9. PR을 생성하고 검증 후 병합한다.
10. 작업 브랜치를 삭제한다.
